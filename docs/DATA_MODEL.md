# Data model

Event: id (stable usage-event hash or random DNS id), time (Unix milliseconds), kind (APP_RESUMED, APP_PAUSED, DNS_REQUEST), value (package or normalized domain), source, observed UID if available. Evidence is OBSERVED for this event only.

Registry classification: domain, organisation, categories, source URL, dataset revision/digest. Evidence is CLASSIFIED; tracker category does not show what a specific request did. UI always shows observation and classification separately. Unsupported names and absent/corrupt records are UNKNOWN. INFERRED reserved for later; no inference is produced by M0.

Usage events report OS lifecycle transitions; no session duration is fabricated when endpoints are missing. Multi-window and background jobs make foreground context unsuitable as a network-owner join. DNS requests are not attached to app events. A unified chronological view is correlation by time, not causation.

M1 PersonalDataGraph: `OrganisationEvidence(name, domains)` → `DomainEvidence(domain, events, classification?)` → original Event IDs. Classification provides categories, dataset source URL and revision. Unknown domains have no classification or organisation edge. App events are a separate list, never attached to DNS events. Domain counts and request counts are distinct. Groups and categories are sorted deterministically; repeated event IDs count once. Graphs are derived only from retained events, so expired or erased records disappear on refresh. No inferred edges or extra persistence are added.

M2 `DayFacts`: selected LocalDate, ZoneId, generatedAt, calendar start/endExclusive, retention boundary, scoped Events and PersonalDataGraph. `SummaryClaim`: stable claim ID, OBSERVED/CLASSIFIED/UNKNOWN level, deterministic text and supporting Event IDs. `DailySummary.evidence` resolves IDs only within that day. No INFERRED claim is produced. Structured facts separate distinct apps resumed, DNS request events and normalized domain names. Empty evidence yields no narrative claim; pause-only evidence does not fabricate a resume. No additional data is written to disk.

M3 `DayStory`: the selected DailySummary plus chronological StoryChapters. A chapter groups events by a 15-minute epoch-time bucket, retains every original event and its separate provenance graph, and records cumulative DNS request and distinct-owner totals. Display timestamps include the timezone offset so repeated DST hours stay distinguishable. Intro and recap use the complete day snapshot; chapters use their own events. Empty buckets create no synthetic scenes. No story is persisted or exported.

M4 `PrivacyProfile`: exact dataset owner name, official policy/choices URLs, review date, contact/deletion/verification guidance and automation disabled. Unverified fields are not guessed. `PrivacyRequest`: UUID, owner, request kind, draft body, creation time, and ordered `RequestUpdate(status,time,reference)` history. Absence is NOT_REQUESTED; a new saved record is PREPARED. Status changes require valid transitions and references. Sent wording and prior updates cannot be rewritten through the editor. The encrypted requests table authenticates `request:id:created`, distinct from event AAD. It has explicit removal instead of the event purge schedule. Public entries have no implication that a user is a customer or that an organisation holds their data.
